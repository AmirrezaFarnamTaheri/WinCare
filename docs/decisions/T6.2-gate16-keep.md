# T6.2 Decision: Ubuntu CI Gate 16 (development_package)

**Date:** 2026-08-01  
**Analyst:** cleanup sweep (Ultra Review Plan)  
**Outcome: KEEP — gate 16 provides unique safety signal**

---

## What gate 16 does

```bash
# Gate 16 — runs on Ubuntu (github-hosted ubuntu-latest)
python tools/build_release.py . --output-directory artifacts/release
VERSION=<extracted from WinCare.psd1>
python tools/verify_release.py "artifacts/release/WinCare-$VERSION.zip" \
    --output artifacts/archive-validation.json
```

It builds the **development archive** (`.zip`) on Linux and validates it with
`verify_release.py` (v2 verifier — generic archive contract: manifest, checksums,
required files, no `.exe`).

---

## What the Windows job does (not gate 16)

The Windows job (`windows-2022`, `windows-2025`) runs a completely different path:

- `build_release.py` → produces both `.zip` **and** the standalone `.exe`
- `verify_release_v3.py` → validates the **standalone archive** with PE header
  checks, `AssemblyProduct`, size gates, and Windows runtime execution
- `WinCare.ps1 --verify` → full PowerShell module lifecycle on a real Windows runner

---

## Unique signal provided by gate 16

| Coverage dimension | Gate 16 (Ubuntu) | Windows job |
|---|---|---|
| Build is reproducible on Linux | ✅ | ✗ |
| `build_release.py` cross-platform correctness | ✅ | partial (Windows path assumptions) |
| v2 generic archive contract (`verify_release.py`) | ✅ | ✗ (uses v3) |
| PE header / standalone exe validation | ✗ | ✅ |
| Real Windows PowerShell lifecycle | ✗ | ✅ |
| SBOM, attestation, provenance | ✗ | ✅ |

Gate 16 is the **only** gate that verifies the development package builds and
validates correctly on Linux. It catches:

1. Path separator bugs in `build_release.py` that would fail on case-sensitive filesystems
2. Python stdlib usage that differs between platforms (`os.path.join` edge cases, encoding)
3. Regressions in `verify_release.py` (v2) that would not be caught by v3

---

## Decision

**KEEP gate 16.** It is not duplicating the Windows job; it covers the
Linux-reproducibility and v2-verifier dimensions that the Windows job does not.

Removing it would leave a blind spot: a PR that breaks `build_release.py` on Linux
would only be detected at release time on a different artifact type.

---

## Future consideration

If the project ever adopts fully hermetic builds (Nix, Bazel, reproducible-builds),
gate 16 could be replaced by a binary hash comparison. Until then, keep it.
