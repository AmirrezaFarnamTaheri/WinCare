# T6.2 Decision: Ubuntu CI Gate 16 (`development_package`)

**Date:** 2026-08-01
**Updated:** 2026-08-05
**Outcome:** KEEP — gate 16 provides a distinct cross-platform packaging signal.

## Current behavior

```bash
python tools/build_release.py . --output-directory artifacts/release
VERSION=<ModuleVersion from src/WinCare/WinCare.psd1>
python tools/verify_release.py "artifacts/release/WinCare-$VERSION.zip" \
    --output artifacts/archive-validation.json
```

`verify_release.py` emits the `wincare.archive.validation/v3` contract. It requires
`RELEASE-MANIFEST.sha256`, `SBOM.spdx.json`, and `BUILD-RECEIPT.json`; validates
exact archive membership, package-input hashes, the SBOM, checksums, path safety,
and the development package profile.

## Relationship to Windows validation

The Windows lifecycle jobs also invoke `tools/verify_release.py` for the archive.
They add Windows-only coverage: PowerShell module import and lifecycle tests,
native build and provenance checks, standalone executable validation, installer
and upgrade paths, and Windows runtime behavior.

| Coverage dimension | Gate 16 (Ubuntu) | Windows jobs |
|---|---:|---:|
| Linux/case-sensitive packaging behavior | Yes | No |
| Deterministic development archive | Yes | Yes |
| Archive v3 membership, hashes, SBOM, and receipt | Yes | Yes |
| Windows PowerShell lifecycle | No | Yes |
| Native/standalone executable validation | No | Yes |
| Installer and upgrade validation | No | Yes |

## Decision

Keep gate 16. Its archive-verifier coverage overlaps intentionally with Windows,
but its Linux filesystem and cross-platform packaging execution are unique. It
catches path-separator, case-sensitivity, encoding, and platform-assumption bugs
before release packaging reaches Windows-only stages.

Reconsider only if packaging becomes hermetic and the same package-input tree is
proved identical across platforms by a stronger reproducibility gate.
