`D:\GitHub\winport`. It records what the current WinCare source already covers,
which ideas are worth promoting through WinCare's typed command and approval
boundaries, and which archive material must remain reference-only. It is not an
implementation inventory or a claim that every archived behavior was evaluated.

`D:\GitHub\winport\_inventory_extract_20260912` on 2026-09-12, alongside the
current command catalog, remediation catalog, policy model, and native-migration

## Current WinCare convergence point

WinCare has already converged on a different execution model from the archive
set:

- The stable command surface is `src/WinCare.CommandCatalog/Data/commands.json`
  with a frozen 259-ID baseline and 268 currently admitted routes, while `src/WinCare.Infrastructure/Commands/WindowsCommandExecutor.cs`
  is the explicit native execution boundary.
- Reusable privacy, maintenance, and hardening changes are typed in
  `src/WinCare.CommandCatalog/Data/remediation-rules.json` and composed by
  `src/WinCare.CommandCatalog/Data/presets.json`; loading and schema validation
  live in `src/WinCare.CommandCatalog/RemediationCatalog.cs` and
  `RemediationCatalogValidator.cs`.
- Mutations retain preview/receipt admission in
  `src/WinCare.Application/Commands/CommandDispatcher.cs`; an archived script
  or executable cannot enter this path directly.
- Native cleanup is bounded in `native/wincare-core/src/cleaner.rs` and the
  managed executor. Policy gates are documented in `policy/README.md` and
  represented by `policy/examples/organization-policy.json`.
- The release boundary intentionally excludes executable legacy PowerShell;
  see `docs/migration/finalization-status.md` and
  `tools/finalize_native_release.py`.
