## Fixed findings

1. Rust formatting failures in pipe-server, daemon, and main sources.
2. Two redundant maximum operations rejected by Clippy with warnings treated as errors.
3. Moved toast XML reused after ownership was transferred to the file writer, preventing compilation.
4. Missing integration-test crate documentation rejected by the new lint configuration.
5. Plugin registry coalesced incompatible `List<string>` and `string[]` types, preventing managed compilation.
6. Plugin store called a nonexistent `forceRemoteRefresh` parameter. The corrected call requests a refresh before checking revocations.
7. Installer silently accepted inline signature claims without an external trust assertion. The existing failing security test now passes.
8. Seekable package streams positioned near their end bypassed the archive size admission limit. Admission now checks the entire stream consumed by ZIP processing.
9. Already-cancelled or invalid-timeout process requests could start a child before failing. Cancellation/deadline setup now precedes process launch.
10. Guard client reused one-shot connections and raced concurrent callers. Connect/send/read/close now share one lock and each command closes its connection.
11. Guard client could wait indefinitely for an unresponsive peer. Exchanges have a five-second deadline; incomplete responses are rejected, and caller cancellation still propagates.
12. Guard server blocked on idle clients, could leave workers alive across restart, and could discard unread responses. Nonblocking pipe polling checks shutdown and deadlines; lifecycle operations are serialized; response consumption has a bounded grace period. Remote pipe clients are rejected.
13. Batch arguments could inject shell operators despite use of `ArgumentList`. Control/expansion syntax is rejected, and cmd autorun is disabled. Script cancellation propagates to the dispatcher and exception details are not copied into user-facing activity messages.

## Extended audit and UI fixes

The subsequent pass fixed atomic command policy/handler registration and duplicate
plugin registration, startup retry after synchronous cancellation, stale preview
approval after selection/parameter changes, background-thread catalog updates,
and cached All Tools page subscriptions. The app now shares its tool catalog
instead of creating a permanent registry subscription on every Doctor page visit.

Journal history is bounded in memory while retaining active operations. Unfinished
records from a previous session become Needs Attention; null persisted records
no longer crash startup. Activity refreshes while visible and displays local times.
Saved preferences normalize null lists, duplicates, and oversized recent history.

Home now displays recent recorded activity and active plugin widgets. Cards and
actions stack at narrower widths, and widget descriptions wrap. Checkup labels
describe collection completion instead of claiming a health score. General Doctor
queries recommend diagnostic checks without claiming the machine is healthy;
cancelled classification propagates cancellation and old plans are cleared.

Numeric parameters reject NaN/infinity. Profile downloads validate IDs, bound
response size, dispose HTTP resources, and reject truncated encrypted files.

rejects symbolic links, and enforces installer size/entry limits.
